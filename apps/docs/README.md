# @zerotal/docs

The site at `zerotal.dev`: the documentation tree, the API reference, the Flow
showcase, the blog — and the writing desk the blog is edited from.

## Running it

```bash
bun install
bun zt key:generate      # writes APP_KEY into .env
bun run seed             # author account + imports blog/*.md into the database
bun run dev              # http://localhost:3000
```

`bun run seed` is idempotent: it creates nothing that already exists, so it is
safe to re-run against a database you have been writing to.

## Where the content lives

| Section                | Source                                                   |
| ---------------------- | -------------------------------------------------------- |
| `/docs/*`              | `docs/*.md` at the repo root, rendered per request       |
| `/api/*`               | `docs/api/`, generated by `bun run docs:api` (TypeDoc)   |
| `/showcase/*`          | `app/showcase/`, live Flow pages                         |
| `/blog`, `/blog/:slug` | the `posts` table **first**, falling back to `blog/*.md` |

Posts have two homes on purpose. `blog/*.md` is the committed set, so a fresh
checkout has a populated blog with no database. The `posts` table is what
`/admin` writes, and a row **shadows a file of the same slug** — which is why
seeding imports the files: after that, every post can be revised in the browser
without a redeploy, and the files stay in git as the origin of the content.

## The writing desk — `/admin`

Flow pages behind `AuthMiddleware`. Because Flow middleware is persistent, the
guard re-runs on every WebSocket update, not only on the initial page load.

| Route                     | Page                                                                                                                                           |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `/admin/login`            | `LoginPage` — `Auth.attempt()`; Flow relays the session cookie over a one-time HTTP request, since a WebSocket frame cannot carry `Set-Cookie` |
| `/admin`                  | `PostsPage` — live search, publish/unpublish, delete, numbered pager                                                                           |
| `/admin/posts/new`        | `PostEditorPage` with nothing bound                                                                                                            |
| `/admin/posts/:post/edit` | the same page; `:post` resolves to a `Post` **by slug** (`Post.resolveRouteBinding`) and `@param` seeds it before `onMount`                    |

### The block editor

`/admin/posts/:post/edit` renders the article in its published styling rather
than as a form. Clicking a paragraph swaps **that block alone** into a textarea;
blur, "Done", or clicking another block commits it and it re-renders.

Prose blocks — paragraphs, headings, lists, quotes — are edited as **rich text**,
in place: the editable element sits in the article's own prose flow and carries
no styling of its own, so a heading stays a heading and a list stays a list while
it is being written. A toolbar floats above the live block (bold, italic, links,
heading level, lists, quote) and the only other affordance is a hairline down the
left margin, so the page still reads as the article rather than as a form. Nobody
has to know what `##` means. The block's HTML is converted back to Markdown on
commit by `htmlToMarkdown()`.

Nothing in that subtree may carry `not-prose`: it excludes its whole subtree from
prose styling — including from a nearer `prose` ancestor — which silently
collapses an `<h1>` to body text. The toolbar itself is `not-prose`, since it is
chrome rather than content.

Code fences, tables and embedded HTML are edited as **plain text** instead.
`blockKind()` decides, and the split is the whole safety story: a round trip
through a `contenteditable` is exactly what turns a code fence into soup, and
these posts are mostly code fences. Whatever cannot survive the trip never takes
it — and it is also what a non-technical author is least likely to touch.

Two test files pin that:

- `tests/markdown-blocks.test.ts` — every committed post survives split/join
  byte-for-byte, fences and all.
- `tests/html-to-markdown.test.ts` — the serialiser's whole surface, plus a
  render-and-read-back round trip over every prose block of every real post.

Storage is always Markdown. There is no HTML in the `posts` table.

`form.body` stays the single source of truth; blocks are derived from it on
every render, so a body set any other way — the **Source** toggle, `fill()`, a
test — shows up immediately and there is no second copy to fall out of step.

Because only the focused block is an input, Flow's DOM morph is free to repaint
everything else without touching a caret.

### Categories

`POST_CATEGORIES` in `app/models/Post.ts` is a closed set — the blog's filter bar
is only legible while it stays short, and free text drifts into near-duplicates
that split one topic across several pills. Adding one means adding a tile to
`CATEGORY_TILE` in `routes/blog.ts`; the tiles stand in for thumbnails (no post
carries an image), so pick a hue that separates from the cream page rather than
another pale tint.

The index filters through plain `?category=` links, not a client-side widget, so
each filtered view is a real URL that can be shared and indexed and the page
still works with JavaScript off. An unknown category falls back to the full list
rather than rendering an empty page.

Posts sort on `publishedAt` — the full instant, not the displayed day. Posts
published on the same date would otherwise fall through to an alphabetical
tiebreak that ignores publication order; the seeder folds each file's `order:`
front matter into the timestamp for the same reason.

A post is a draft until `publishedAt` is set, and a draft is invisible to
`/blog` — including when it shadows a committed file.

### Notes for anyone extending it

- **Forms patch as one object.** A `value={this.form.title}` binding sends the
  whole `form` key on the wire, not a dotted path, so `onUpdated()` fires with
  `"form"`. Don't branch on `"form.<field>"` — it never arrives.
- **`this.errors.<field>` is never undefined.** It returns an `ErrorField`
  sentinel, so it is always truthy and stringifies to `[object Object]`. Render
  it with `<ErrorMessage for={this.errors.email} />`, which binds the field and
  reveals itself only when there is an error; use `this.errors.has(field)` when
  you need a plain boolean.
- **`Post.publishedAt` is a `Carbon`, not a `Date`** (the `datetime` cast).
  Compare with `.isPast()`, assign with `Carbon.now()`.
- **Mass assignment is narrow.** `Post.fillable` is the four fields an author
  types; `publishedAt` and `authorId` are assigned by the server on the way past.
- **Tests need a request scope.** `FlowTest` drives a component's lifecycle but
  opens no request, and these pages read the session and the request. Wrap calls
  in `RequestContext.run(HttpContext.fake(url), …)` — see `tests/authoring.test.ts`.
- **A model field needs `static models = { Post }`.** Without it the synth cannot
  match the class, so the field dehydrates to a plain object and returns from a
  WebSocket action with its data but none of its methods. It fails on the second
  interaction, never the first, and `FlowTest` does not round-trip through the
  synth — so only a browser catches it.

## Crawlers and feeds

`routes/seo.ts` serves three things, all built from the same post list the blog
renders:

| Path             | What it is                                                      |
| ---------------- | --------------------------------------------------------------- |
| `/robots.txt`    | Allows everything, disallows `/admin`, points at the sitemap    |
| `/sitemap.xml`   | The landing page, `/blog`, every doc page, every published post |
| `/blog/feed.xml` | RSS 2.0, newest 20 posts, `guid` = permalink                    |

All three build absolute URLs from `APP_URL` — **set it in production**, or the
sitemap will advertise `localhost` to Google.

The sitemap deliberately omits the listing's `?category=`/`?sort=`/`?view=`
views: they are the same posts rearranged, and every one carries a
`<link rel="canonical">` back to a bare `/blog`. Listing them would be asking to
be indexed as duplicates.

`/blog/feed.xml` is an exact route registered alongside the `/blog/*` post
wildcard; Bun's router prefers the exact match, and a test pins that so the feed
cannot silently start 404ing as a post slug.

## Deployment

**Run the migrations.** `config/database.ts` builds the schema from the models
at boot _only_ outside production. In production that is off and `zt migrate` is
the only thing that creates tables — deploy without it and every page that
touches `posts` fails:

```bash
bun zt migrate
ADMIN_PASSWORD=<something real> bun run seed   # first deploy only
```

The seeder refuses to run outside local without `ADMIN_PASSWORD`, and refuses
the literal `password`. That account can publish to the live site.

**Set `APP_URL`** (canonical URLs, sitemap, feed, OG tags) and, if the app sits
behind a load balancer, **`TRUSTED_PROXIES`** to the number of proxies in front
of it. The sign-in rate limit keys on the client IP; `X-Forwarded-For` is
client-writable, so without that count the limiter falls back to the socket
address and every visitor behind the balancer shares one bucket.

**Back the database up.** Posts written at `/admin` exist only in the SQLite
file — the committed `blog/*.md` set is the origin of the imported posts, not a
copy of anything written since:

```bash
bun run db:backup             # → storage/backups/db-<timestamp>.sqlite
bun run db:backup --keep 30   # retention (default 14)
```

It uses `VACUUM INTO`, which snapshots a database that is being written to;
`cp` on a live SQLite file can yield a torn copy. Run it on a schedule, and ship
the snapshots somewhere off the box — a backup on the same volume as the
original is not a backup.
